# Independent staged-DCF validation, frozen 2026-09-13

This is a separate workbook from `independent_dcf_validation_v2.xlsx`. It does not change the valuation engine, trade policy, statement source, or deployment. The V2 workbook covers the earlier flat forecast and is not claimed to validate this staged path.

## Evidence and construction boundary

The four real-company inputs come from the committed, dated JSON snapshots in `../snapshots/` (MSFT, CAT, INTC, VZ). Their SHA-256 hashes are checked against `../snapshot_manifest.json` before the workbook is built. Statement values are frozen SEC-derived XBRL facts with fiscal ends, filing dates, tags, and source filing URLs; market price, shares and beta are frozen Yahoo observations retrieved 2026-08-17. The fifth case is explicitly synthetic: 2021–2025 annual revenue rises from $1.0B to $1.2B while EBIT is −20% each year, with hypothetical balance-sheet, tax and market inputs dated 2026-09-13. No live data is fetched. AAPL is excluded because its complete source-traced snapshot was not available.

The workbook was authored from `docs/model-specifications/dcf.md` and `docs/model-specifications/wacc-capm.md` at `c5ccbd41b6423c09cbc1851e8245139a0a3b7c72` before reading production calculation code. Each issuer tab contains every frozen input, unit, source/date, and fallback/derivation status, followed by workbook formulas for historical CAGR/margin/tax/debt cost, WACC, each of five annual growth/margin/revenue/FCF steps, discounted FCF, terminal value, enterprise/equity value, and Bear/Base/Bull per share. The `Scorecard` keeps mathematical completion separate from economic quality; the `Policy and limits` sheet exercises zero and threshold equality/adjacency cases. Inputs are blue; formula outputs are black or cross-sheet links.

The written specification states a two-year near-term phase, a three-year linear fade of growth *above* 3%, and flat margins, but does not numerically define the interpolation points or the Bear/Bull shifts. This validator uses remaining excess fractions 2/3, 1/3, 0 for years 3–5 and explicitly records that interpretation. Its independent scenario convention is growth ±2 percentage points, margin ±1 point, WACC ∓1 point, and terminal growth ±0.5 point. These are **validator assumptions**, not documented product policy and not inferred from production code. Consequently, Bear/Bull value differences from production are not model failures or price calibrations. The written specification should pin these numbers if full scenario reconciliation is desired.

The workbook and `frozen-results.json` were calculated and saved before `compare_after_freeze.py` imported application code. The post-freeze check compared 140 intermediate Base values across the five cases: applied WACC; all five annual growth, margin, revenue and FCF values; undiscounted and discounted terminal value; discounted annual FCF; enterprise value; equity value; value per share; and terminal share where defined. All 140 passed. Largest absolute difference was `1.39e-17` (floating-point rate); dollar quantities were identical at the shown precision. Tolerances: rates `1e-10` absolute, money `max($0.01, 1e-10 × |workbook dollars|)`, value per share `$0.01` absolute. The independent workbook has seven worksheets, 1,112 formula cells, and zero exported spreadsheet error cells. The four real snapshot hashes matched the manifest.

## Bear/Bull independent reconciliation (follow-on, frozen 2026-09-13)

This workbook's own Bear/Bull cells (above) were never a valid reconciliation — they used a guessed scenario convention, not production's. `docs/model-specifications/dcf.md` ("Bear / Base / Bull scenarios") and `docs/assumptions-register.md` (`A-029`, `A-030`) now pin the actual production fade fractions, scenario deltas, and staged-path shift/clamp rule in writing (see `L-021` in the limitations register for the full gap description). This workbook's Excel-authoring tool (`build.mjs`, via `@oai/artifact-tool`) is not available outside the environment that produced the original xlsx, so the follow-on independent calculation is a plain Python module instead — same independence discipline (fresh formulas from the spec text, frozen before any comparison), different authoring tool:

- **`independent_scenarios.py`** — imports nothing from `src.dcf_model`. Reuses this workbook's own already-reconciled Base per-year growth/margin path, WACC, and tax rate (from `frozen-results.json`, itself 140/140-validated) as the three fixed inputs a scenario shifts, and independently re-implements, from the pinned spec text only, the staged per-year conditional shift/clamp rule (`shift_staged_rate`), the FCF projection, the Gordon Growth terminal value, and the discount/bridge-to-per-share math. Run directly, it writes `frozen-results-scenarios.json` and prints its SHA-256; that file is the frozen, pre-comparison evidence — do not hand-edit it.
- **`compare_scenarios_after_freeze.py`** — the production side of the comparison (legitimately imports `src.dcf_model.scenarios.compute_dcf_scenarios`), comparing the frozen independent Bear/Bull per-share values, per-year-1 growth/margin, WACC, and terminal growth against production for all five cases.

**Frozen file hash**: `frozen-results-scenarios.json` SHA-256 is `15dc9a7ae94665d1812292bb01122ef8fc785f55f6624f9f5e116c234ed99421`.

**Result**: all 50 comparisons (5 cases × 2 scenarios × 5 metrics: per-share, year-1 growth, year-1 margin, WACC, terminal growth) passed, with a maximum absolute difference of `0.0` — an exact float match, not merely within tolerance for these five metrics specifically. The full machine-readable report is present in this worktree (**untracked, not committed** — see "Git status" below) at `scenario_reconciliation_report.json` (SHA-256 `81f69cfabe357501d79c6430ca257124997d2962481568a27ccf82bb8061d36c`). No exceptions among the checks it ran.

This is a real, exact match on the five metrics it checks, but it is a narrow slice of the full Bear/Bull calculation — it does not check years 2–5 of the growth/margin path, revenue, FCFF, discounted FCFF, terminal value, its present value, enterprise value, or the equity bridge. **v2 (below) extends coverage to all of those and is the fuller reconciliation** — read this v1 result as "no evidence of a problem in what it checked," not as evidence the full calculation chain agrees.

**Independence caveat (applies to both v1 and v2 below)**: this validator's *calculation code* is independent — it imports nothing from `src/dcf_model/scenarios.py`. But its *policy discovery was not blind*: the author had already read `scenarios.py` directly before writing either validator module (that reading is what produced `A-030`'s pinned deltas and shift/clamp rule in the first place). This differs from the original Base workbooks (V1/V2, and this directory's own Base section above), which were authored from specification text *before* reading `dcf.py` at all — the kind of blind re-derivation that caught the genuine `L-019`/`A-028` specification gap. An exact match here is real evidence the *code* matches the now-pinned policy; it is not evidence of the stronger kind a blind second author would provide. See `L-021` in the limitations register for the full discussion.

**Known defect in this frozen file's own description, left uncorrected**: `frozen-results-scenarios.json`'s `scenarioConvention` field reads "WACC -/+1pp", which describes Bear as −1pp / Bull as +1pp — the **reverse** of what was actually computed (Bear +1pp / Bull −1pp, confirmed correct in the file's own numeric `wacc` values and in `A-030`). Because this file is frozen, hash-pinned evidence, its bytes are deliberately **not** edited to fix this — that would defeat the purpose of freezing it. v2's equivalent description string is generated programmatically from the delta constants themselves specifically so this class of hand-transcription error can't recur.

## Bear/Bull v2 — full intermediate reconciliation plus boundary fixtures (frozen 2026-09-13)

v1 (above) established exact agreement on 5 metrics per case. v2 extends this to every intermediate in the Bear/Bull calculation chain, plus nine synthetic boundary fixtures targeting specific clamp/threshold mechanics that none of the five real/synthetic-company cases happen to trigger.

- **`independent_scenarios_v2.py`** — imports v1's already-independent formula functions (`shift_staged_rate`, `project_fcf_path`, `terminal_value`, `discount_and_bridge`, the pinned bound/delta constants) rather than duplicating them, and assembles a fuller per-scenario result: all five years' growth, margin, revenue, and FCFF; each year's discounted FCFF; the terminal value and its present value; enterprise value; the debt/cash equity bridge (equity value); and per-share value. It also defines nine synthetic boundary fixtures (documented in its own module docstring) isolating: growth clamping when the baseline is in-bounds, growth left unclamped when the baseline is already out-of-bounds, margin clamping at both the 0% and 60% edges, WACC clamping at both the 5% and 20% edges, terminal-growth clamping at both the 0% and 5% edges, and one case (`uncomputable_bull`) where Bull's WACC and terminal growth both clamp to exactly 5%, making the scenario uncomputable (`WACC <= g`), while Bear in the same fixture remains computable for contrast. Run directly, it writes `frozen-results-scenarios-v2.json` and `frozen-manifest-v2.json` (recording both this file's own hash and the hash of the `frozen-results.json` it depends on) and prints both hashes.
- **`production_scenario_capture.py`** — a validation-only wrapper around the actual production functions (not a reimplementation): it calls the real `_shift_staged_rate`/`_clamp` (private but genuine production functions in `scenarios.py`) followed by the real `project_free_cash_flows_from_path`, `calculate_terminal_value`, `discount_to_present_value`, and `calculate_intrinsic_value_per_share` from `dcf.py`, in the same sequence `_compute_scenario` runs internally, purely to capture intermediates that `ScenarioResult`/`ScenarioAssumptions` don't expose. It changes nothing in `src/`. A second function, `capture_via_public_api`, calls `compute_dcf_scenarios` directly and is used as an internal fidelity check that the wrapper's hand-orchestrated call sequence hasn't silently diverged from the real public entrypoint.
- **`compare_scenarios_v2_after_freeze.py`** — before any comparison, recomputes the SHA-256 of both `frozen-results.json` and `frozen-results-scenarios-v2.json` and aborts if either doesn't match `frozen-manifest-v2.json` (verified to actually abort against a deliberately corrupted copy during this validation, then restored). Writes **every** comparison row, passes included, to `scenario_v2_reconciliation_report.json` — not only failures — so the report is auditable independent of this README's summary.

**Frozen file hashes**: `frozen-results-scenarios-v2.json` SHA-256 is `af6880e6bbbf252d714cabfda71aec052f2def4700166c9d221fb6ed9b6d58fb`; `frozen-manifest-v2.json` records this alongside `frozen-results.json`'s unchanged SHA-256 (`4de5f3e4665bd3d6fcf74ea674084d18590c428fc866bab41e404f785349e200`, confirmed identical to the hash documented in "Frozen result and reconciliation" above — the Base freeze this module reads from was not touched).

**Result**: 1,036 total comparisons (5 companies + 9 boundary fixtures, × 2 scenarios each, × per-year growth/margin/revenue/FCFF/discounted-FCFF [5 years × 5 metrics = 25] + WACC + terminal growth + terminal value + PV terminal + enterprise value + equity value + per share [7] + invalid-reason-presence [1] + three wrapper-fidelity cross-checks + their own invalid-reason check [4] = 37 per case × 28 cases = 1,036) — **0 failures, 0 exceptions**, maximum absolute delta `1.53e-05` (well inside the `money`/`share` tolerances used). The boundary fixtures behaved exactly as designed: e.g. `growth_clamp_in_bounds`'s Bull growth clamps to the 40% ceiling; `growth_unclamped_out_of_bounds`'s Bear/Bull both stay below the −10% floor, unclamped; `uncomputable_bull`'s Bull case reports `invalid_reason = "WACC must exceed terminal growth rate..."` while its Bear case (same fixture) computes a valid per-share value. Full row-by-row report (present in this worktree, **untracked**) at `scenario_v2_reconciliation_report.json` (regenerate to get its current hash; not itself hash-pinned, since it is v2's own output artifact rather than frozen pre-comparison evidence).

This does not, by itself, make the ±3pp/±2pp/∓1pp/∓0.5pp policy deltas themselves more economically justified — see `A-030`'s "If wrong" note — only that the code correctly implements the now-pinned policy, subject to the independence caveat above (policy discovery was not blind).

## Reproduction

All three reconciliations are read-only against whatever `src/` currently contains — none of them mutate `src/`, and none should be run against a dirty `src/` tree if the result is meant to describe a specific commit.

**Original workbook (Base, xlsx).** From the isolated worktree, run the artifact-tool builder with its bundled Node runtime and module path, then preserve the workbook and JSON hashes before running `PYTHONPATH=. .../python3 validation/independent_dcf/staged_v3/compare_after_freeze.py`. The builder is `build.mjs`; it uses the artifact-tool spreadsheet runtime (`@oai/artifact-tool`, not available outside the environment that produced the original xlsx — see "Bear/Bull independent reconciliation" above), not production DCF outputs. Do not run the comparator until a fresh independent build is frozen. The preview PNGs generated outside the repository were visually inspected for the scorecard, policy boundaries, each company's evidence/input section, forecast, scenarios and quality labels.

**Bear/Bull v1 and v2 (Python).** From an environment with this repository's Python dependencies installed (`numpy`, `pandas`; see root `requirements.txt`), from the repository root: `PYTHONPATH=. python3 validation/independent_dcf/staged_v3/independent_scenarios.py` (v1) or `PYTHONPATH=. python3 validation/independent_dcf/staged_v3/independent_scenarios_v2.py` (v2) to regenerate and re-freeze — only if deliberately revising the independent calculation, since this overwrites that version's frozen file(s) and invalidates any prior comparison against them; v1 and v2 are independent freezes and regenerating one does not touch the other. Then run the matching comparator to check the current freeze against current production code: `PYTHONPATH=. python3 validation/independent_dcf/staged_v3/compare_scenarios_after_freeze.py` (v1) or `PYTHONPATH=. python3 validation/independent_dcf/staged_v3/compare_scenarios_v2_after_freeze.py` (v2, also re-verifies both frozen files' hashes against `frozen-manifest-v2.json` before comparing).
